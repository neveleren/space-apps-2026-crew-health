# Tests: what is checked, how to run it, and tonight's results

Every automatic check of the program, the four browser checks that walk the real pages, and what they gave on 15 Nov 2026. Version 1.2.0.

Written by Claude (Anthropic), an AI system, for team Just For Fun. The idea, the structure and every decision belong to the team's human member; the code and the tests were generated by Claude. A passing test shows that the code does what the drafts say; it does not show that a draft threshold is right. The team and the flight surgeons decide those.

## Run the automatic checks

Needs Node.js 18 or newer. No packages: the tests use Node's own test runner.

```
npm test                                   all 17 test files, offline
node --test tests/engine.test.js           one file
```

The two live checks call the real services (NASA ISSLive through Lightstreamer, and NOAA SWPC), so they need the internet. They are skipped unless `JFF_LIVE=1` is set:

```
$env:JFF_LIVE = '1'; npm test              PowerShell
JFF_LIVE=1 npm test                        bash
```

- `npm test` runs the files listed in `package.json` (`scripts.test`). A new test file must be added to that list, or it does not run.
- The server checks (`tests/serve.test.js`, `tests/store.test.js`) start `serve.mjs` on a random port (20000 to 39999), most of them with a throwaway data folder in the system's temporary folder, and delete it afterwards. Two checks work inside the app folder and clean up after themselves: one uses a throwaway data folder there under another name (`zz-records-<process id>`), and one writes a small test file into `data/` to prove that it is never served.
- `tests/cycle-log.test.js` starts `serve.mjs` once, on a port from 25230 to 25249 (another one if that is taken), with a throwaway data folder, and deletes it afterwards.
- The other files need no server and no network (the two live checks aside): they import the modules and read the files they check. Where a test needs a browser part (the page, storage, Bluetooth), it builds a small stand-in.

## Browser checks (Playwright, not part of `npm test`)

Four scripts walk the real pages in a headless Chromium, as a person would: they click, type, read the screen and catch page errors. They are **not in this repository** and not in `package.json`. They need Playwright for Node and a Chromium build, installed separately (`npm install playwright`, then `npx playwright install chromium`). Each script names the path of its Playwright package and of its browser near the top; change those two paths on another computer. Tonight they ran with Playwright 1.64.1 for Node and Playwright's Chromium headless shell, revision 1254.

### How to run them

Start a server with a throwaway data folder for each script, so one walk never sees another's records:

```
DATA_DIR=/tmp/jff-e2e PORT=8121 node serve.mjs                  bash
$env:DATA_DIR = "$env:TEMP\jff-e2e"; $env:PORT = '8121'; node serve.mjs     PowerShell
```

Then, from the folder that holds the scripts:

```
node e2e.cjs http://127.0.0.1:8121/ out/e2e
node mind_test.cjs http://127.0.0.1:8122/ out/mind
node mind_test.cjs http://127.0.0.1:8123/ out/mind-phone phone
node integ_test.cjs http://127.0.0.1:8124/ out/integ
```

For the static copy, serve the app folder with a plain file server (no API, no security headers), for example Python 3's, and point the check at it:

```
python -m http.server 8125 --bind 127.0.0.1                       in the app folder
node static_check.cjs http://127.0.0.1:8125/
```

- Each script prints PASS or FAIL for every step, then the page errors; all but `static_check.cjs` end with the totals. Screenshots go to the output folder; `static_check.cjs` takes none and has no output folder.
- `integ_test.cjs` uploads `tests/fixtures/hexoskin.csv` from a fixed path written in the script.
- The server loads its rules (`src/security.js`, with `src/config.js`, `src/engine.js` and `src/quicklog.js`) once, when it starts, while the page files are read fresh on every request. Restart the server after changing those files, or the page and the server can disagree, and then saves are refused with 400.
